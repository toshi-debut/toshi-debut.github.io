# 投資デビュー診断

大学生向けの「投資デビュー診断」Webアプリ。

**無料は「気づきと診断」、有料(300円買い切り)は「具体的なプラン」**という
はっきりした線引きで作っている。

## 公開URL

**https://toshi-debut.github.io/**

GitHub Pages で公開している(無料)。`main` ブランチに push すると
1〜2分で自動的に公開版が更新される。

```powershell
cd "toshi-debut-shindan"
git add -A
git commit -m "変更内容"
git push
```

将来 Stripe の決済を入れる場合、GitHub Pages は静的ファイルしか置けないため
サーバー側の処理が書けない。そのときは同じ GitHub リポジトリを
**Netlify** か **Cloudflare Pages** につなぎ直せばよい(どちらも無料枠で
サーバー側の関数が使え、コードの作り直しは不要)。

### 公開名義について(重要)

このリポジトリは **`toshi-debut` という組織アカウント** で公開している。
個人アカウント名を URL に出さないためで、リポジトリ名を `toshi-debut.github.io`
にしてあるので URL からリポジトリ名も消えている。

コミットの作者情報も、個人が特定されないように
`toshi-debut <toshi-debut@users.noreply.github.com>` に統一している。
この設定はこのリポジトリだけに入れてある(`.git/config`)ので、
**フォルダを作り直したり clone し直したときは、もう一度これを実行すること。**

```powershell
cd "toshi-debut-shindan"
git config user.name "toshi-debut"
git config user.email "toshi-debut@users.noreply.github.com"
```

うっかり本名でコミットしていないかは、これで確認できる。

```powershell
git log --format="%an <%ae>" | Sort-Object -Unique
```

`toshi-debut <toshi-debut@users.noreply.github.com>` の1行だけなら OK。

### 独自ドメインに変えたくなったら

`toshi-debut.com` のようなドメインを取れば(年1,000〜4,000円程度)、
GitHub Pages 側は設定画面でドメインを登録するだけで切り替わる。HTTPS 化も無料。
ただし**ドメイン登録時は「Whois情報公開代行」を必ず有効にする**こと。
忘れると氏名・住所・電話番号が公開データベースに載る。

切り替えたときは `app.js` の `SHARE_SITE.url` も直すこと(共有リンクに使っている)。

## 使い方(起動方法)

このフォルダの `index.html` をダブルクリックしてブラウザで開くだけで動く。
サーバーもインストールも不要。

友人に見せるときは、この `toshi-debut-shindan` フォルダごと渡すか、
`index.html` と `app.js` の2ファイルを同じ場所に置いて渡せば同じように動く。

### ローカルサーバーで確認したい場合(任意)

```powershell
cd "toshi-debut-shindan"
python -m http.server 8000
```

ブラウザで `http://localhost:8000` を開く。

## 画面構成

### 0. 導入画面(無料)

アプリを開くと最初に出る画面。フォームはまだ出さず、期待感を作ることに専念している。

- キャッチコピー「大学生のための投資デビュー診断」
- 「収入と支出を入れるだけ。3分であなたに合う投資スタイルと、無理なく続けられる毎月の金額がわかります。」
- 収入は「バイト代」と限定せず、仕送り・奨学金なども含む言い方に統一している
- **診断人数カウンター**「すでに 12,480人 の大学生が診断済み」(カウントアップ演出つき)
- 「3分でわかる」「投資タイプの判定まですべて無料・登録不要」という価値の提示
- 特徴3点(住まい別/平均比較/タイプ判定)
- **「診断をはじめる」ボタン**を押して初めて入力フォームへ進む
- ビジュアルは上下に浮くアイコンと、外へ広がる波紋のアニメーション

### 0.5 途中データの自動保存と再開

収支入力 → 5問診断のあいだ、**入力するたびに内容がブラウザの localStorage に自動保存される**。
途中でページを閉じても、次に開いたときに「前回の続きから再開しますか?」と聞かれる。

| | 動き |
|---|---|
| 保存するもの | 住まい・全部の金額・5問の回答・どこまで進んだか |
| 保存するタイミング | 住まいの選択 / 金額の入力 / 診断ボタン / 設問に答えるたび |
| 消えるタイミング | **5問の診断が終わってタイプが確定した瞬間**、または「いいえ、最初からやり直す」を選んだとき |
| 保存先 | この端末のこのブラウザの中だけ。サーバーには一切送らない(通信するコードが無い) |

再開ダイアログには「5分前の入力内容が残っています」「住まい: 実家暮らし / 入力した項目: 6件 /
診断の回答: 3 / 5問」のように**前回どこまで進んだか**が出る。
壊れた保存データ・古い形式(`v` が違う)・すでに5問答え終わったデータは無視して、最初から始める。

保存キーは `toshi-debut-progress`、処理は `app.js` の `saveProgress()` / `loadProgress()` /
`restoreProgress()` / `clearProgress()`。**別のスマホやPCには引き継がれない**点に注意。

#### 進捗の常時表示

入力〜診断のあいだ、画面上部に**スクロールしても残る進捗バー**(`#progress-strip`)を出す。
有料画面ではタブバーが同じ位置に固定されるため、進捗バーは出さない。

| 状態 | 表示 | 進捗 |
|---|---|---|
| 住まい未選択 | 📝 住まいを選ぶ | 0% |
| 収支を入力中 | 📝 収支を入力中 | 10% |
| 診断結果の画面 | ① 余裕額 〜 ⑤ 詳しいプラン | ドット + n/5 |

計算は `progressState()` にある。

### 1. 入力フォーム(無料)

最初に **「一人暮らし / 実家暮らし」** を選ぶと、その住まいで実際にかかる項目だけが出る。

| | 一人暮らし | 実家暮らし |
|---|---|---|
| 収入 | 働いて得た収入(アルバイト等) / その他の収入(仕送り・奨学金など) | 同左 |
| 固定費 | 家賃・光熱費・通信費・サブスク | 家に入れているお金・通信費・サブスク |
| 変動費 | 食費・交遊費・カフェ/コンビニ・交通費・日用品雑費・趣味娯楽 | 食費(自分の分のみ)・交遊費・カフェ/コンビニ・交通費・趣味娯楽 |

- 食費と交通費は、比較に使う平均額と注記も住まいごとに切り替わる
- 住まいを切り替えても入力済みの金額は保持される
- 余裕額の計算は「収入 − 表示中の項目の合計」で共通(非表示の項目は 0 扱い)
- 金額欄はすべて **3桁カンマ区切りで表示**(内部では数値のまま保持)
- 入力するそばから各セクションの合計額が更新される
- **収入が0のままでは診断できない**。支出は未入力でも通すが、収入が無いと余裕額も平均比較も
  すべて0になって診断が成立しないため、理由を出して止める(`validateForm()`)

### 2. 診断結果(無料・5ステップ)

縦に長くならないよう、結果画面は**5つのステップに分割**して1つずつ読み進めてもらう。
ページの再読み込みはせず、同じ画面の中で表示を切り替える(`showStep()`)。

| ステップ | 内容 | 進み方 |
|---|---|---|
| **① 余裕額** | 余裕額のカウントアップ / ひとことコメント / 見落としがちな支出 / 同世代比較 | 「次へ」 |
| **② もし投資していたら** | 機会損失プレビュー / 生活防衛資金の注意 | 「次へ」・「戻る」可 |
| **③ タイプ診断** | 誘導コピー + 5問の診断 | 5問目で**自動遷移** |
| **④ 診断結果** | タイプカード / 回答の振り返り / 同じタイプとの比較 / SNS共有 | 「次へ」。**戻るは置かない**(診断のやり直しになるため、代わりに「もう一度診断する」) |
| **⑤ 詳しいプラン** | 有料の目次プレビュー / なぜ今始めるか(折りたたみ) / 利用者の声 / FAQ / 価格 + 課金ボタン | 「戻る」可 |

- 進捗は上部の固定バーに **ドット5個 + 「3/5」** で表示(狭い画面ではドットを省く)
- 切り替えは `stepIn` のフェード+スライド。`prefers-reduced-motion` で停止する
- 診断し直したときは、進んでいたところ(未診断なら①/診断中なら③/診断済みなら④)に戻る

#### ステップ①の中身

- **余裕額はカウントアップ演出**で表示。カードは順に浮き上がって出る
- **同世代平均との比較**は、まず収入合計と支出合計を見せ、項目ごとの内訳は折りたたむ
  (項目を全部並べるとスマホで長すぎるため)
- **平均より多く使っている項目トップ2**と年間差額を、比較カードの下に添える

#### 比較に使う平均額(公式統計)

**出典: 全国大学生活協同組合連合会「第60回学生生活実態調査」**
(2025年2月28日発表 / 2024年10〜11月調査 / 有効回答 11,590人)

調査の費目とアプリの入力項目は一対一で対応しないため、次の方針で割り当てている
(`app.js` の `EXPENSE_ITEMS` の上のコメントに全文あり)。

| 方針 | 対象 |
|---|---|
| 調査値をそのまま使う | 交通費・電話/通信費・日常費・住居費(自宅生)・アルバイト |
| 1つの費目を複数項目に分ける(**内訳は推定**、合計は調査値と一致) | 住居費→家賃+光熱費 / 食費→食費+カフェ・コンビニ / 教養娯楽費→サブスク+交遊費+趣味娯楽 |
| 平均から除く | 書籍費・勉学費・その他(アプリで聞いていないため。ユーザー側も入力しないので、除いたほうが公平に比べられる) |

推定した項目には `est: true` を付けている(家賃・光熱費・サブスク・食費・交遊費・カフェ・趣味娯楽)。

| | 一人暮らし(下宿生) | 実家暮らし(自宅生) |
|---|---|---|
| 収入合計 | 132,140円 | 68,370円 |
| 支出合計(アプリで比較する範囲) | 111,960円 | 40,940円 |

出典は画面上にも小さく明記している。収入も同じ調査値と比較できる。

#### ステップ②:機会損失プレビュー(`renderOpportunity()`)

余裕額を年5%で20年積み立てた場合の金額を**1つだけ**大きく見せ、
貯金だけの場合との差を一言添える。利回り別のグラフなど詳しい試算はここでは出さず、
「診断の最後にご用意しています」と書いて期待を作る。前提は `OPP` にある。

あわせて**生活防衛資金**(余裕額の8割を投資・残りは手元・生活費2ヶ月分が先)を出し、
煽るだけで終わらないようにしている。

#### ステップ⑤:課金への導線

| # | セクション | 中身 |
|---|---|---|
| 8 | **目次プレビュー**(`PAID_TOC`) | 有料の5項目をタイトル+説明+🔒で一覧 |
| — | なぜ今始めるか | 早く始める効果 / 1年先延ばし / インフレ の3計算。**既定は折りたたみ** |
| — | よくある質問 | `FAQ_ITEMS` のアコーディオン |
| 10 | **価格の見せ方** | ¥300を大きく + 「☕カフェのコーヒー1杯分」+ 買い切り/追加課金なし/月額ではありません |
| 11 | **CTA** | ぼかし越しのプレビュー + 脈打つアニメーション付きの「300円で全部見る」 |

### 3. 架空データについて(重要)

**診断人数カウンターと「利用者の声」は表示していない。**
実際の利用者データが無いまま実績のように見せると、有料課金を始めた段階で
景品表示法の「優良誤認表示」に該当するおそれがあるため。

コード自体は消さずにコメントアウトして残してある。
実データが集まったら、`index.html` と `app.js` の
「【一時的に非表示】」「【一時的に無効】」のコメントを外し、
`DIAGNOSED` / `REVIEWS` を実データに書き換えれば復活する。

同じ理由で、タイプ別の金額は「利用者の平均」ではなく
**「このタイプの積立額の目安」**という表現にしている(`TYPE_STATS`)。

### 4. よくある質問(無料・課金の壁の手前)

購入前の不安を解消するためのアコーディオン(`<details>`)。4件。
内容は `app.js` の **`FAQ_ITEMS` 配列**で管理している。

- この診断は本当に当たっていますか? → 診断ロジックの説明と、利回りは仮定である旨
- 支払い方法は何がありますか? → クレジットカード想定・買い切り・現在は未実装である旨
- 診断結果は保存できますか? → 1080×1920のシェア画像として保存できる旨
- 投資の知識が全くなくても大丈夫ですか? → 用語ツールチップとやることリストの案内

### 5. 課金の壁

有料コンテンツの中身が **ぼかし(blur)越しに透けて見える**。
プレビューは選んだタイプの実データで作られるので、「自分の結果が隠れている」状態になる。
「¥300で全部見る」ボタンは光るアニメーション付き。

### 6. 詳細プラン(有料・タブ切り替え)

スクロールが長くなりすぎないよう、**上部固定のタブ5枚**で切り替える。

| タブ | 内容 |
|---|---|
| 📈 積立試算 | **積み上げ棒グラフ**で5年ごとの資産額を表示(元本と運用益を色分け、ホバー/タップで正確な金額と合計を表示)。金額(0〜10万)・期間(1〜40年)・利回り(3/5/7%)を動かすと即再計算。チェックを入れると3利回りを並べた棒グラフに切り替わる。「あと月+1,000/3,000/5,000円」の差額比較つき |
| 💼 投資プラン | タイプ別のテーマ分散ポートフォリオ。商品名の例つき |
| 🎯 目標逆算 | 目標(留学・車・世界一周・結婚資金・タワマン頭金・早期リタイア・自由入力)から必要な毎月の積立額を逆算。「あと月◯円」「◯年◯ヶ月遅れる」を提示 |
| ✅ やること | 5ステップのチェックリスト。進捗バー・完了バナーつき。状態は localStorage に保存 |
| 📱 シェア | LINE / X / Instagram の共有ボタンと、**Instagram ストーリーズ用の 1080×1920 画像**の生成・ダウンロード |

どのタブからでも他のタブへ移動できる。タブバーはスクロールしても上に固定される。

## 計算方法

毎月積み立てた場合の将来価値(月複利の年金終価):

```
FV = 毎月の積立額 × ((1 + r/12)^(年数×12) − 1) / (r/12)
```

例: 月1万円・年5%・20年 → 4,110,337円(元本240万円 / 運用益171万円)

目標からの逆算はこの式を積立額について解いたもの。
**必要額は切り上げ**ている(切り捨てると、その額を積み立てても目標にわずかに届かないため)。

## デザインの方針

- **白ベース固定**。OSのダークモード設定には追従しない
- 配色はネイビー(信頼) × グリーン(成長) × ゴールド(特別感)
- 演出：カウントアップ / カードのフェードイン / 課金ボタンの発光 /
  タイプカードのポップイン。すべて `prefers-reduced-motion` で無効化される
- 用語ツールチップ：NISA・インデックスファンドなど11語を辞書化し、
  文中の該当語を自動でボタン化(`GLOSSARY` と `AUTO_TERMS` に追記すれば増やせる)

## 操作性・アクセシビリティ

| | 対応 |
|---|---|
| スマホの「戻る」 | 画面遷移を `history.pushState` に積んでいるので、**アプリごと離脱せず1つ前の画面に戻る** |
| キーボードだけの操作 | 診断は **1/2/3キー**、有料のタブは **←→キー**、やることリストは Space / Enter |
| ダイアログ | `role="dialog"` + `aria-modal`。**Escキーで閉じる**。開いたらボタンにフォーカスが移り、閉じると元のボタンに戻る |
| タブ | `role="tablist"/"tab"/"tabpanel"` で紐づけ。選択中以外は Tab キーで飛ばす |
| 読み上げ | 余裕額と診断結果に `aria-live="polite"`、入力エラーに `role="alert"`、グラフに代替テキスト |
| 動きを減らす設定 | すべてのアニメーションが `prefers-reduced-motion` で止まる |

## 自動スクロール

新しく出てきた内容が画面の外にあって気づかれない、ということが起きないよう、
表示が変わる場所では `scrollToEl()` でその先頭まで運ぶ。

| きっかけ | スクロール先 |
|---|---|
| 住まいを選ぶ | 出てきた入力欄(`#form-body`) |
| 収入未入力で診断を押す | エラー表示(`#form-alert`、画面中央) |
| 診断する / 画面を切り替える | ページ先頭 |
| 次の設問へ進む・前に戻る・受け直す | 診断カード(`#quiz-card`)の先頭 |
| **5問目に答えて結果が出る** | **タイプ結果カード(`#type-card-wrap`)の先頭** |
| 有料のタブを切り替える | タブバー(`#tabbar`) |
| 「表で見る」を開く | 表(`#table-wrap`) |
| 結果カードを作る | できた画像(`.share-frame`) |
| Instagram共有を押す | 保存の案内(`.social-note`、画面中央) |

- `behavior` は `prefers-reduced-motion` で `smooth` / `auto` を切り替える
- 上に固定されるバーの下に隠れないよう、着地位置の余白は
  **CSS の `scroll-margin-top`** で確保している(スマホでは少し詰める)
- 進捗バーとタブバーはどちらも `position: sticky; top: 0` なので、
  **有料画面では進捗バーを引っ込めて**重ならないようにしている

## 壊れにくくするための作り

- **Chart.js が読み込めなかった場合**(オフライン・CDN障害)でも有料画面は落ちない。
  グラフの場所に理由を表示し、**金額の表を自動で開く**ので数字はそのまま読める
- localStorage が使えない環境(プライベートモード等)でも try/catch で握りつぶして動作は続く
- 保存データが壊れている・形式が古い場合は無視して最初から始める

## 決済(クレジットカード + PayPay)

### 今の状態

**アプリ側の実装は完了している。あとは Stripe で「支払いリンク」を作って貼るだけ。**

`app.js` の先頭にある `STRIPE` に、テスト用・本番用のキーとリンクを分けて持たせてある。

```js
const STRIPE = {
  mode: 'test',                       // 'test' か 'live'
  test: { pk: 'pk_test_...', link: '' },   // link に支払いリンクを貼る
  live: { pk: '', link: '' },
};
```

`link` が空のあいだは、購入ボタンが「¥300 を支払う(準備中)」になり、
押しても料金は発生せず有料画面が開く（動作確認用）。
`link` を入れた瞬間に本物の決済に切り替わる。**コードの書き換えは不要。**

> **pk_ のキーをソースに直接書いてよい理由**
> `pk_`（公開可能キー）はブラウザに配ることを前提に設計されていて、
> これだけでは決済の作成も返金も残高照会もできない。
> 絶対に書いてはいけないのは `sk_` で始まるシークレットキーのほう。
> こちらは Netlify に移したあと、サーバー側の環境変数に入れる。
> テストで「`sk_` が混入していないか」を毎回チェックしている。

### 支払いリンクの作り方（Stripeダッシュボード）

1. 「商品カタログ」→ 商品を作る（300円・一括）
2. 「支払いリンク」を作成
3. **支払い後の遷移先を必ず `https://toshi-debut.github.io/?paid=1` にする**
4. できた `https://buy.stripe.com/...` を `STRIPE.test.link` に貼る

### 決済の流れ

```
購入ボタン
  → 診断内容を localStorage(toshi-debut-return)に預ける
  → Stripe の決済画面へ移動
  → 支払い完了
  → https://toshi-debut.github.io/?paid=1 に戻る
  → 診断内容を復元し、有料画面を開く
  → toshi-debut-paid を立てる / toshi-debut-return を消す / URLから ?paid=1 を消す
```

### 支払いの確認（Netlify）

**本体は GitHub Pages のまま。支払いを確認するプログラムだけを Netlify に置いている。**
これで、URL に手で `?paid=1` と付けただけでは有料機能が開かなくなる。

```
支払い完了
  → https://toshi-debut.github.io/?paid=1&session_id=cs_test_xxx に戻る
  → session_id を Netlify の verify に渡す
  → verify が Stripe に「この支払いは本物か」を問い合わせる
  → paid: true が返ったときだけ有料画面を開く
```

| ファイル | 役割 |
|---|---|
| `netlify/functions/verify.js` | 支払いを Stripe に確認するプログラム |
| `netlify.toml` | Netlify に「確認プログラムだけ置く」と伝える設定 |
| `netlify-public/index.html` | Netlify 側を直接開いた人への案内ページ1枚 |

**アプリ側の設定は `app.js` の `STRIPE.verifyUrl`。**
ここが空のあいだは確認できないので、`?paid=1` をそのまま信じてしまう。
**販売を始める前に必ず埋めること**（テストで空でないことは検査していないので注意）。

#### シークレットキーの置き場所

`sk_` で始まるキーは**コードに一切書かない。** Netlify の管理画面に登録する。

```
Netlify → Site configuration → Environment variables
  STRIPE_SECRET_KEY_TEST = sk_test_xxxxx
  STRIPE_SECRET_KEY_LIVE = sk_live_xxxxx
```

支払い番号が `cs_test_` で始まればテスト用、`cs_live_` なら本番用のキーを使い分ける。
**両方登録しておけば、本番に切り替えるときに `verify.js` を直す必要はない。**

#### 安全のために入れてあること

- 呼び出せるのは `https://toshi-debut.github.io` からだけ（CORS）
- 支払い番号の形をしていないものは、Stripe に問い合わせる前に弾く
- 返すのは `{ paid: true / false }` **だけ**。購入者のメールアドレスなどは外に出さない
- 確認できなかったときは有料画面を開かず、問い合わせ先を案内する

### 審査・動作確認用のURL

| URL | 何が起きるか |
|---|---|
| `?review=checkout` | サンプルの診断結果を入れて、購入画面を直接開く |
| `?paid=1` | 支払い完了として戻ってきたときの動き |

`?review=checkout` は、Stripe / PayPay の加盟店審査で
「審査担当者が決済画面まで到達できること」を求められるために用意した入口。

(Netlify Functions か Cloudflare Workers の無料枠で足りる。上の「公開URL」参照)。

### 本番の決済を開始するときの手順

4. `STRIPE.mode` を `'live'` に変える
5. `tokushoho.html` 冒頭の「🛠️ 決済機能は準備中です」バナーを**削除**する
6. 自分で1回、実際に300円を払って通しで確認する
